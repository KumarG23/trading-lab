# Hourly swing-agent paired shadow experiment — proposal, not activated

Status: proposed 2026-10-04. This document changes no frozen V3 rule, service, risk cap, broker permission, or order path. The goal is to recover the original agentic-trader question: does a reasoning agent add *incremental after-cost decision value* over a local model and simple rules on the same prospective opportunities?

## Why this experiment

The archived Claude_Bot had an agent deciding on recurring cycles, but its large prompts and many hold calls made inference expensive. The preserved `trades.db` presently has 17 trade records and aggregate negative recorded trade P&L before Claude charges; five have null net P&L and the recorded Claude cost is incomplete. This does not rule out a different profitable period or accounting error. Reconcile the old bot's trade records with its paper-broker statements before using historical profitability as a premise. Do not reuse old prompts or outcome-labeled Claude examples as a performance benchmark.

## Pilot design (freeze exact rule and activation before the first observation)

- Scope: liquid U.S. equities/ETFs, long-only, regular-session hourly completed-bar scans; deterministic scanner produces a bounded, deduplicated set of opportunities, holds and no-trades. No crypto/options. Start with a 1–3 trading-day intended hold as a distinct **swing shadow** hypothesis; enforce a time exit and model overnight-gap risk. Exchange calendar gates weekends/holidays/early closes. Change the horizon only in a new version, never retroactively.
- For each candidate, freeze a compact, timestamped **market-only** information packet after a completed hourly bar. Include source/feed/cutoff, price/volume/context, and candidate identity; exclude account balances, credentials, private logs, later bars and outcomes. Hash the packet and log each model/version/prompt, response time, failure, token usage and measured compute/usage cost.
- Feed the **same packet** to (A) a restricted, rate-capped Codex reasoning call and (B) a qualified local inference model, plus (C) a deterministic rule/no-trade control. Model outputs are strictly parsed opinions: long/abstain, thesis, invalidation, confidence and uncertainty. Neither lane gets broker/order tools or private account files; Codex runs in an isolated read-only sandbox with a sanitized market-only packet, and cannot write into the research ledger directly. Every candidate remains in the denominator regardless of a model abstention or failure.
- Freeze one conservative counterfactual plan generator independent of model opinion. Resolve candidate outcomes with completed bars, next-available-entry/no-fill logic, adverse gaps, stop-first ambiguity, slippage and fees. Apply the existing $200 notional/$2 planned-risk ceiling as a *research simulation*, not real capital or permissions. Evaluate 1–3 day outcomes only after they finish; exclude missing/ambiguous data rather than label it a win. Track unfilled and overnight exposure separately. Do not confuse summed independent shadow returns with an executable portfolio equity curve.
- Compare same-candidate, same-session decisions: after-cost expected/net R, coverage/abstention, calibration, drawdown under a separately specified portfolio-shaped simulation, regime slices, and inference latency/cost. Use chronological development and untouched future holdout; count independent issuer/session groups rather than raw hourly duplicates. Repeated prompts/model variants belong in the multiple-testing ledger. Do not promote on one lucky week or a text-model narrative.

## Sequence

1. Audit legacy Claude_Bot aggregate accounting against broker-paper records (read-only; no raw private trade export) and inventory a licensed/available local model on existing hardware. First assess existing services; do not wake a parked server or buy hardware by default.
2. Implement an offline paired harness and deterministic fixtures. Prove same frozen snapshot to all lanes, no future data, no broker/account access, stable parsing, safe failures, and cost accounting.
3. Preregister the actual candidate/horizon/risk/outcome rule, then activate a **read-only** hourly shadow collector and record first-seen timestamps. Run a small operational smoke; monitor completeness and runtime. Frozen earnings V3 runs separately as a control.
4. Once independent fully resolved forward observations exist, train a calibrated CPU tabular baseline on decision-time features and compare it with both reasoning lanes and simple controls. Fine-tune a small licensed language model only for extraction/journal quality if a held-out task evaluation justifies it; do not teach it to imitate profitable hindsight trades.
5. Broker-connected paper orders require a separate explicit approval and a risk/authorization design. Live money is a further gate. If a lane is negative after costs or underpowered, report that, keep it shadow-only, and change the next hypothesis prospectively.

This is an experiment specification, not a claim that the prior bot was profitable, that the local model is free to run, or that hourly trading will make money. Inference has electricity/hardware/usage cost; execution still has spread, slippage, gaps and losses.
